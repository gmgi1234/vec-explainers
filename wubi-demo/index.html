把 12 万个页面，换成「一个模板 + 一份数据」

不是换技术栈，只是不再给每个字预先生成一份一模一样的 HTML。

现在是什么样

现在的做法

  • 121,835 个 HTML 文件
  • 磁盘占用 3,024 MB
  • 一个「狗」字页 66 KB
  • 同一张字图在页里画了 3 次（86/98/新世纪各一份）
  • 字根小图又重复十几遍
  • GitHub Pages 软上限 1 GB，超了 3 倍

改完是什么样

  • 1 个模板 + 1 份数据
  • 每个字只存 一条记录（约 5 KB）
  • 字图只存 一份，三版渲染时复用
  • 查什么字，就把参数放进地址栏
  • 体积降到原来的 1/10 左右

它是怎么工作的

现在：/site/char/狗.html      ← 12 万个文件，每个自带全套 CSS + JS + 字图
改后：/char.html?c=狗         ← 1 个文件，按参数查 data.js 里的记录

浏览器打开 ?c=狗
   → 读 data.js 里「狗」那一条
   → 把编码、字根、字图填进模板
   → 页面画出来

点一下试试（这就已经在跑了）

同一份模板，地址栏换参数就是另一个字；页面标题也会跟着变。

全站推算是多少

现在改后
文件数121,835几十个（按拼音分桶，比如 a 桶、b 桶…）
磁盘3,024 MB约 300–600 MB
能不能放 GitHub Pages超软上限 3 倍能，且还有余量
打开速度每次下载整套模板模板走缓存，只取一个桶的数据

有一个代价，得说清楚

SEO。现在每个字都有独立 URL、独立标题和描述，搜索引擎能一个一个收录——这是这套站最大的流量来源。改成动态页之后，搜索引擎只看到一个 char.html。

折中方案（我推荐这个）：热门字保留静态页（几百到几千个，撑起收录），冷门字走 ?c= 动态渲染。既保住 SEO，又把 12 万文件降到几千。

跟现在这套代码的关系

生成器里「算编码、拆字根、算颜色」的逻辑一行都不用改，只是最后一步从「写 12 万个 HTML」改成「往 data.js 里追加一条记录」。字根数据、配色、拆分规则全部沿用。
